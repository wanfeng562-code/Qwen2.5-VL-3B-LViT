# 阶段二至四实验结果与验收记录

完成日期：2026-11-01。云端项目：`/root/autodl-tmp/Qwen2.5-VL-3B-LViT`。本轮按任务书先完成 MoNuSeg；cov19、MosMedData 仅完成描述与定位试点，尚未完成其正式分割训练。

## 结论

阶段二至四已完成：LViT 现代环境适配与真实学习/恢复验证、60张医学图像的 Qwen 描述及定位试点、MoNuSeg 两种文本条件各三个种子的训练与独立测试、单图串联推理和实际分割图审查。

**冻结 Qwen 普通描述在本次设置中没有带来增益。**其测试平均 Dice 比原有文本条件低 1.9339 个百分点，IoU 低 2.3929 个百分点，三个配对种子的差值均为负。该结论仅针对本轮固定数据和接口，既不证明 Qwen 普遍无用，也不支持声称方法有效。原有文本来源未独立证实；本对照不是纯图像模型消融。

## 阶段二：适配与训练验收

沿用 base 环境 Python3.12.3、Torch2.5.1+cu124、torchvision0.20.1+cu124、Transformers4.51.3，仅添加 timm1.0.15、opencv-python-headless4.11.0.86。pip依赖检查与Qwen回归加载通过。LViT 使用上传源码快照，39,933,345参数，从头训练，未改变 vendor 网络或载入旧检查点。

图像采用 BGR、双线性224、除255；掩码原灰度>0后使用 OpenCV INTER_NEAREST 到224；预测阈值≥0.5，双空样本Dice/IoU=1。两组使用相同固定清单、BERT权重、25位置截断/WordPiece合并/前10位置接口、优化器和评价。Adam lr=0.001、batch=2、FP32、weight_decay=0、余弦热重启T0=10/Tmult=1/min_lr=0.0001，禁用TF32并使用确定性算法，无几何增强。

44张真实数据加载通过；原损失和适配损失在混合、全空、全前景的值与梯度零差异。两张训练图100步过拟合：损失0.56293→0.06629，Dice96.0748%；这只是学习能力检查，不是测试成绩。保存恢复后下一次更新的模型、Adam、scheduler和loss完全相同。实际两轮训练及已结束任务的恢复检查通过，未额外更新。

六组稳定训练吞吐中位数约13.09–13.47图/秒（不含检查点I/O）；Torch分配峰值2.7373GiB、保留峰值3.2266GiB。Qwen和BERT在训练前生成缓存，正式LViT训练不运行它们。当前约32GB可见显存足以运行本次已验证流程；本轮未测两个模型同时驻留训练。

完整差异与兼容性边界见 [LViT适配说明](LViT适配说明.md)。现代Hugging Face BERT与旧MXNet/Gluon实现不宣称数值等价，因此本结果属于统一协议下的适配复现。

## 阶段三：描述与定位试点

60张全部来自训练/验证：MoNuSeg30、cov19和MosMedData各15。后两者按大小、连通域和图像质量覆盖选择，不能当作总体随机抽样。GT仅用于选样与独立评价，没有作为生成输入。提示在train/val校准后冻结，之后才生成MoNuSeg测试描述。

v1因不适合的坐标约定和提示中占位例子的照抄失败，原始输出及失败报告保留。v2明确使用模型实际缩放输入的绝对像素坐标，再转换为下游归一化坐标；移除了字面占位示例。原始严格结构有效率0/60；只去围栏仍为0/60；明确允许“去完整围栏＋顶层数组包装”的固定合同适配后60/60。适配不修改描述、坐标或缺失字段，不等于医学质量达标。

**分支选择：**普通短描述已冻结完成受控比较；空间框尚不足以支撑可靠的多区域融合。阶段五前先改进定位或评估医学适配，当前没有启动LoRA，也没有完成空间融合。详情见 [阶段三视觉审查](阶段三视觉审查.md)。

## 阶段四：缓存、成本与串联推理

最终44张普通描述使用相同v2模型/提示/参数：30张复用已冻结试点，14张测试图新生成。44张唯一图像的生成计时合计60.2637秒，预处理合计5.1729秒；不把复用成本误算为本次新增墙钟。新增14张生成器内部墙钟26.0444秒（含模型加载3.2625秒），外部子进程墙钟39.7832秒还包含启动和完整指纹校验。全流程试点探索另有开销，不包含在正式LViT训练墙钟里。

## 限制、返工与下一步

本轮最大的工程返工是Qwen坐标/JSON合同校正，以及Pillow与OpenCV最近邻采样差异修正。前者保留了失败v1并只在train/val调整，后者按冻结训练口径重算了受影响评价；模型和测试协议没有事后更改。更合适的后续流程是先验证少量真实图的尺寸、原始输出、掩码像素对应和文本接口，再生成批量证据，避免只凭“可解析”判定可用。

目前的负结果不能唯一归因于某个模块。可见候选问题包括泛化且重复的短描述、前10位置接口的信息压缩、原有文本可能含额外标签信息，以及仅14张测试图和三个种子的有限规模。下一轮应先在训练/验证集检验文本是否被模型利用（固定文本/打乱文本等控制）并改善定位质量，再决定是否进入空间融合或LoRA；这些属于后续任务，未在本次测试集上继续调参。按既定顺序扩展cov19、MosMedData时，仍需披露已有病例/序列交叉。
