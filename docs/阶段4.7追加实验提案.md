# 阶段4.7追加实验提案：保留原基线的Qwen视觉残差

状态：提案，尚未实施或启动正式训练。阶段4.5与4.6共使用17/18次正式训练。本提案最多再9次，需将累计上限明确调整为26次；不能把剩余1次自动扩展为新搜索。

## 为什么考虑这条路线

当前结果支持Qwen视觉特征在新结构中有贡献，却没有证明整套方案超过旧LViT。此前验证集也只显示候选比固定对照高0.4278个百分点，信号有限。本提案用于分离“增加Qwen信息”与“改变原文本接口/基础网络”的影响，不把本次测试成绩用来挑层、阈值或种子。

原始14张测试图已经多次查看。新一轮若开展，所有配置和选择仍只看24张训练图与6张验证图，14张仅允许锁定后的单次描述性复测，不称新盲测。若要形成更强的泛化结论，还需独立数据验证，本提案不擅自新增或下载数据集。

## 唯一候选与不变项

仅设一个新候选R，不再搜索视觉层、提示、分辨率或LoRA：复用已冻结的Qwen第16个block视觉缓存，使用既定28×28、1280维空间特征。

保留旧版LViT、原有文本及其原编码缓存；三个种子分别从先前仅按验证集选出的旧原文本基线检查点出发。旧LViT参数和BatchNorm统计冻结，原网络一直处于eval状态；只训练新增视觉残差投影与门控。残差仍注入最终解码特征，门控从0开始，首次输出必须与对应旧模型逐元素一致。代码单独版本化，不改旧核心或检查点。

这验证的是“原文本框架加Qwen视觉特征”，不是自动描述替代原文本，也不是纯图像部署方案。原文本来源尚未独立证实，此限制须贯穿报告；不能声称未知来源文本在真实部署时自动可得。

预处理、损失、Adam lr0.001、FP32、batch2、24/6/14和666/667/668不变；max2000/min50/patience50不变。旧基线作为epoch0候选检查点，只按最高验证Dice选模，平分选最早。所有条件统一使用这条规则。优化器仅管理新增参数，不继承旧Adam状态。

## 正式训练前的工程检查

这些是接线与恢复检查，不构成正式分割实验，最多3个更新步：

- 使用真实train/val输入验证零门控与旧基线输出逐元素一致。
- 旧参数及BatchNorm统计在更新前后hash不变；优化器只包含新参数。
- 零门控第一步的投影梯度可以为0，但门控必须有有限有效梯度，门控更新后投影必须获得梯度；不能用no_grad把冻结输出层对新增分支的梯度截断。
- 保存、重载与下一步更新一致；缓存、ID、训练均值及划分内错位规则核验。
- 不读取新测试结果来决定是否改实现。接线失败先修工程问题，不冒充正式实验结果。
